Topology (`environment/docker-compose.yaml`):

- `main`: the agent container, built from the repository root with `environment/Dockerfile` on `node:24-bookworm-slim` (multi-arch index digest `sha256:d6aa754f16b3197301076f047b5def2f02ea1dbbc2ca920407d46d7ec7f87b20`, resolved 2026-10-07) for the host's native architecture: no `platform` is pinned, because nothing in the image is amd64-only and emulation would slow Harbor's fixed 360 s agent setup and the MCP cold start. It joins the compose `default` network (public egress for the harness's model API and Harbor's agent install) and the internal `nous-eval` network. The verifier also runs here.
- `mock-nous`: a Python standard-library HTTP double (`environment/mock_nous/`, `python:3.11-slim` index digest `sha256:0dd364ba7e10242f07755449e3a3d0e35f9efd987952737b90def6709ab0c5ce`) on `nous-eval` only (`internal: true`, no route out). `main` waits for its `/healthz`.

Main image contents:

- The real harness bridge: `packages/harness-bridge/src` plus its dependencies, installed with `corepack pnpm install --frozen-lockfile --filter @nous/harness-bridge` from the committed root `pnpm-lock.yaml` (every workspace manifest is copied so the frozen check sees the whole workspace; the root `.npmrc` with `node-linker=hoisted` is not copied, so only the bridge's dependency tree is installed). The build runs `cli.ts --help` under the pinned runtime as a load check.
- A pinned Node 24 runtime at `/opt/nous-eval/bin/node` (a copy of the image's node). Harbor's codex install puts an nvm Node 22 first on the agent's `PATH`; the launcher never resolves `node` from `PATH`.
- The stdio launcher `/opt/nous-eval/start-mcp.sh` (`launch.py`, `forwarder.py`), `python3`, and `evals/harbor_common` under `/opt/nous-eval/lib` for the verifier. `/app` (the agent's workspace) starts empty.
- `/tmp/codex-home/config.toml` pre-seeded with `web_search = "disabled"` (key and values checked against codex-cli 0.153.4: `disabled|cached|indexed|live`). Harbor 0.6.6's codex agent uses that `CODEX_HOME` and only appends its MCP entry, so a codex trial has no hosted web search. Claude Code's `WebSearch`/`WebFetch` are removed on the command line (`harness.md`). The mock, its fixtures and `tests/truth.json` never enter this image; `tests/` is uploaded to `/tests` only after the agent finishes.

MCP launch (`start-mcp.sh` → `launch.py`), idempotent because the CLI may spawn the server more than once:

1. Under a file lock, reuse or start a detached TCP forwarder `127.0.0.1:18080 → mock-nous:8080`. The bridge only accepts `https` or loopback `http` API origins (`packages/harness-bridge/src/mcp/client.ts` `apiBase`).
2. Wait (≤ 20 s) until `/healthz` answers through the forwarder.
3. Write the owner-only credential store the bridge's `CredentialStore` requires (`/tmp/nous-eval-<uid>/store`, directory 0700 and file 0600, UUID v4 handle) with fake opaque tokens and no `grantId`, so `GrantKeeper` never calls the renewal endpoint.
4. `execve` the bridge with a clean environment: `node --import <tsx loader> src/cli.ts mcp --api http://127.0.0.1:18080/api/v1 --store <dir> --session <handle>`, the argv shape of `packages/harness-bridge/src/mcp/config.ts`. Nothing but JSON-RPC reaches stdout; launcher and forwarder logs go to stderr and `/logs/agent/nous-mcp/`.

Backend contract served by the double (`mock_nous/server.py`):

- `GET /api/v1/integrations/tools` returns `catalog.json`; `POST /api/v1/integrations/tools/read` takes `{tool_name, arguments, invocation_id}` and returns `200 {content, is_error, source_refs}`. Both require `Authorization: Bearer <token>` and `X-NOUS-Integration-Grant: nous_ig_<43 chars>` (401 otherwise). No redirects; unknown paths 404.
- `catalog.json`, `connectors.json` and `arxiv_query.json` are generated from backend source by `mock_nous/generate_catalog.py` (`list_read_tools(["tools:read"], workspace_bound=False)`; `_tool_list_external_databases({})` with key-gated connector keys unset: 11 connectors, 8 available; `fred`, `alpha_vantage` and `cosmic` unavailable; `tools_impl._ARXIV_STOPWORDS`/`_ARXIV_VENUE_STOPWORDS` and `arxiv_service._ARXIV_QUERY_SYNTAX`). The generator overrides the backend settings it needs regardless of the caller's environment and then compares the mock's ported arXiv query rewrite with the backend helpers on fixed sample queries. `generate_catalog.py --check` exits 0 on a match, 1 on drift (a file or the rewrite), 2 when the generator itself fails.
- Argument validation follows `read_tools._validate_arguments`: unknown keys (including `project_id` on this project grant), missing required keys and wrong JSON types are 422 with the gateway's detail strings; local tools also enforce their schema bounds.
- Result shapes follow `invoke_read`, `_finish` and `_source_refs` plus the `tools_impl` payloads: `search_documents` `{documents, total, query}` newest first (`ORDER BY created_at DESC`, as is `list_project_documents`); `search_arxiv` `{papers[id,title,authors≤3,abstract≤250,published,categories,pdf_url:""], total, query}` where `query` is rewritten as `_tool_search_arxiv` does (`_sanitize_arxiv_query` drops filler, venue and repeated tokens; `field_arxiv_query` adds `all:` AND fielding unless the query already uses arXiv syntax or is all filler; then the `submittedDate` window) with the real empty-result warning, at most 5 papers; `search_external_database` `{query, total_results, results[id,title,source,url,content≤300,authors≤5,published_date,document_type], connectors_searched}` with connector, domain, availability and per-connector filter-key handling as in the registry, and gateway-collapsed `{"error":"upstream_unavailable"}` for an unknown/unavailable connector, an invalid domain or unsupported filters; `list_external_databases` the generated inventory (domain-filtered lists show available connectors only, like `search_by_domain`). The other tools answer consistently with the planted library: `list_project_documents` lists the two documents, `get_document_content`, `do_kb_retrieve` and `retrieve_passages` return short text for planted ids (`requested_documents_unavailable` for foreign ids), `get_arxiv_paper_content` returns a short page for the planted arXiv ids (`arxiv_unavailable` otherwise), `get_current_draft` reports `not_found`, `list_project_artifacts` is empty, and the researcher tools find nobody (the planted documents carry no author metadata).
- `GET /events` returns the JSON list of every `/api/v1/integrations/*` request: `seq`, `t` (monotonic seconds), `method`, `path`, `tool_name`, `arguments`, `invocation_id`, `headers_present{authorization, grant}`, `user_agent`, `status`, and for accepted reads `is_error` and `returned_ids`. It is read-only; nothing but integration requests writes it. Any client in `main` can reach the double (the forwarder, or `mock-nous:8080` directly) and the fake grant is readable in `/opt/nous-eval/launch.py`, so the verifier separates bridge traffic by `user_agent` (`node`, Node's built-in `fetch`; every bridge request in the smoke run) and fails any other client as a bypass. `GET /healthz` is readiness only.

Data: fixtures in `mock_nous/fixtures.json`; the verifier's copy of the planted identifiers is `tests/truth.json`. Topic: retrieval-augmented generation for clinical question answering.

Reset: Harbor recreates both containers per trial, so the event log, forwarder and credential store start empty.

Fidelity limits:

- The NOUS backend is a double. The real parts are the bridge (code, dependency lockfile, credential store checks, HTTP client, MCP SDK server) and the catalog text and schemas the harness reads. Gateway authentication, grants, tenancy, PostgreSQL, Redis, upstream arXiv/PubMed and the agent graph are not exercised.
- Relevance is a keyword match on the lowercased query (any of `retrieval`, `rag`, `clinical`, `question answering`, `medical`, `qa`), not the real ILIKE title match for `search_documents` or arXiv/PubMed ranking. Real `search_documents` needs the whole query to appear in one title, so the double is more lenient than production.
- The arXiv recency window is echoed in the rewritten query but not applied (the planted 2509.* preprints would fall outside the default 365-day window on 2026-10-07).
- `do_kb_retrieve` behaves as if a knowledge base were provisioned; on dev `DO_KB_ENABLED` is false and the real tool reports `reason: disabled`.
- Tokens are fake and only format-checked; the grant never expires (the bridge prints its one-time "predates grant renewal" warning to stderr).
- Codex and Claude Code apply their own MCP server startup timeouts, which Harbor's config writers do not set. The launcher plus bridge answered `initialize` in about 0.9 s on a cold start and 0.2 s on reuse in a local arm64 smoke run; the image builds natively, so no emulation is involved. A timeout surfaces as an infrastructure failure (no catalog request recorded).
- `main` keeps public egress (model API, agent install), so a shell command could still fetch from arXiv or PubMed directly. The instruction forbids sources other than the NOUS tools, hosted web search is off for both harnesses, and any identifier the double did not serve fails the trial as fabrication. An egress allowlist (`evals/harbor_common/templates/proxy`) was not adopted: Harbor's agent install needs several hosts, and the hosted search tools run on the provider side where a proxy cannot see them.
- Bridge identification is by `User-Agent`; a client that deliberately sends `User-Agent: node` would be counted as the bridge.
