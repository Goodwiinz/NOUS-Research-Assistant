## 1. Outcome and boundaries

Plan 04 gives each normal persisted `Thread`, including projectless chats, a maintained context document with honest coverage, source links, owner corrections and pins. External recall reaches only explicitly selected threads. A generated summary, existing project connection, or public workspace visibility confers no export permission.

Plan 05 lets a connected harness explicitly start a bounded NOUS research task in a separately authorized child/idle target thread. The caller receives a durable task ID immediately, can poll or cancel, and receives persisted output when execution actually finishes. Direct tools remain independent. No automatic NOUS/Codex conversation loop, recursion, autonomous follow-up, general mutation permission, or hidden-reasoning export is introduced.

Treat this as two deliverables with a narrow interface: workflows may consume authorized Plan 04 revisions, but document-only workflows do not require Plan 04. Approval covers the decisions below, not simultaneous implementation of both subsystems.

## 2. Alternatives and recommendation

| Approach | Benefit | Cost / reason to choose otherwise |
| --- | --- | --- |
| **Recommended: database invalidation, separate recall authority, restricted native profile and shared dispatch relay** | Covers every message writer, preserves current binding contracts, reuses durable execution/publication, and makes source and budget boundaries enforceable. | Adds explicit schema and policy components; requires serial migration slices and real PostgreSQL proof. |
| Service-owned source increments and expanded existing grant union | Fewer database triggers and one grant lifecycle. | Every message insert/upsert/edit/delete/backfill must adopt the same increment protocol; raw SQL can silently bypass it. A third binding also changes current project/workspace XOR constraints, resolvers, CLI and consumers. Requires a complete writer/consumer migration before safety claims. |
| Read-time summaries and separate workflow engine/queue | Small initial context schema; independent task runtime. | Repeated model cost and inconsistent revision semantics; duplicates native checkpoints, cancellation and publication. A parallel relay contradicts the amendment and creates two recovery owners. |

Select the first approach. Keep document revision triggers narrowly about source identity, keep generated prose out of triggers, and retain native default chat behavior.

## 4. Plan 04: source identity, refresh and reads

**Persistence decision: transactional PostgreSQL triggers.** Add one document per normal `Thread`, immutable generated revisions, exact revision-source manifests, resumable coverage chunks, and independently versioned owner annotations. Document counters are `source_revision`, `annotation_revision`, and monotonic `invalidation_epoch`; retain `current_revision_id`, dirty/error state and fenced refresh lease. Document owner is thread creator, falling back to workspace owner for legacy threads, with current access checked for every correction.

An `AFTER INSERT` thread trigger ensures the document; message triggers ensure it idempotently for legacy threads. The eligible projection is live, unsuperseded user/assistant messages from normal threads. Inserts/appends advance source revision and mark stale. Content/role/stopped/visibility/supersession changes, hard deletes, thread moves, or ordering changes advance invalidation epoch as well. Moving a message invalidates both old and new threads. Backdated inserts invalidate already covered ranges. Feedback-only/irrelevant metadata changes do nothing; `ON CONFLICT DO NOTHING` retries create no revision change. Parent deletion is also checked on every read. Do not create shadow agent-thread documents or regenerate prose in a trigger.

An epoch mismatch suppresses all old generated prose and copied source-bound pins permanently, including after rebuilding. Rebuild never resets the epoch. Standalone user-authored corrections remain labeled assertions; source-bound pins with deleted/superseded sources retain their stored identity but show unavailable text until the owner explicitly resolves them. No hidden metadata, prompts, traces or run-event logs enter the source corpus.

**Refresh contract.** Use a separate `conversation_context_tasks` worker, at most 20 due documents per 60-second tick, with a 120-second fenced lease, bounded per-document transaction/session, debounce of 30 seconds after a write, and retries backing off to at most 15 minutes. Each model page reads at most 100 messages and 64,000 characters in `(created_at,id)` order. Persist a per-message character cursor when a message spans pages; never silently treat a truncated message as covered. Empty threads publish complete zero/zero coverage without a model call. Resume verified chunks only within the same invalidation epoch; append may extend coverage, whereas edits invalidate dependent chunks.

Use the configured `build_lightweight_llm` with temperature 0, structured output, 2,048 output tokens and a 30-second request timeout. Blocks are purpose/decisions/facts/open questions/next steps/resources, with authority and exact message IDs/hashes. Reject invented references and unsupported evidence labels. Assistant assertions are reported claims, not verified outcomes; stopped output is explicitly partial. Model output is untrusted data and cannot become annotations or authority.

Generate outside database locks. Publication compares source revision, invalidation epoch, annotation revision and refresh fencing token captured for that candidate. A loser discards the candidate and requeues; it cannot overwrite newer annotations. Merge annotations by identity outside model rewriting. Partial revisions may be visible with `complete=false`; completeness requires every eligible source character accounted for, no omitted blocks, and a matching source revision. Bounded compaction must preserve provenance/omissions; covered input does not certify semantic fidelity.

Native APIs: `GET /api/v2/threads/{id}/context`, source preview, Markdown export, owner-only annotation replacement with `expected_annotation_revision`, and explicit enqueue-only refresh. Use `workspace_routes/conversation_context.py` plus focused `services/conversation_context/{repository,refresh,access,read,annotations}.py`. Operational backfill belongs in `backend/scripts/backfill_conversation_context.py`: 500-thread keyset pages, committed cursor, idempotent document creation and queueing, no model calls in backfill/migrations. Do not import bulk history into application memory.

Read DTO: current revision/counters, generated time, freshness (`pending/fresh/stale/invalidated/error`), authority-labeled blocks, verified source refs and coverage/omissions. Cap complete serialized responses at 64 KiB, 100 blocks, 2,000 characters/block and 50 source IDs/block. Select whole blocks with their refs; report omissions and incomplete coverage. Oversized annotation replacement is 422, never silently loses pins. Markdown uses this same authorized read result. Expected-current-revision mismatch is 409; no alternate history/export route may bypass source invalidation.

## 5. Plan 04: explicit external recall authority

Create separate `ConversationConsent` / `ConversationGrant` persistence and frozen `ConversationContext(actor,organization,grant_id,consent_id,thread_ids)`. This deliberately revises the old proposal to widen `IntegrationGrantRequest`: current project/workspace constraints and `IntegrationContext` remain intact. A common lifecycle helper may share token hashing/revocation mechanics, but the two resolvers never accept each other's tokens.

Browser approval selects 1–100 exact normal threads and the single `threads:read` capability. Proposed recall consent lasts at most 30 days, displayed in approval; transport grants last 15 minutes and renewal never extends consent expiry or selection. Re-selection creates a new consent; existing snapshots/cursors do not gain threads. Native context generation has no dependency on this consent. No external correction, refresh or write tool exists.

External access intersects selection, current active actor/organization, live thread/conversation/workspace, and owner/live membership. Public visibility alone is insufficient. A null-organization personal workspace uses its current owner's organization; an absent/mismatched organization fails closed externally. Filter this intersection **before** ranking, counts, snippets and pagination. Source previews additionally reject deleted/superseded/system/tool messages and validate exact hashes. A copied text/result cache is never an authorization cache.

Expose `search_nous_conversations` (20 results), `read_nous_conversation` (50 messages/page), and `get_conversation_context`; all responses including refs fit 64 KiB. Oversized source messages use an explicit character continuation. Cursors are signed, expire after 15 minutes, and bind actor, consent selection digest, query, ordered position and relevant source epoch; scope/epoch changes reject them. Reauthorize each page after retrieval and before final serialization. Define the response linearization point: a revocation committed before final authorization denies the page; bytes already authorized/sent cannot be recalled. Coordinate revocation/response reads with the consent row; test both commit orders rather than promise retroactive network cancellation.

Use a protected versioned MCP session descriptor with optional project and conversation **credential handles**, each backed by owner-only `CredentialStore` entries and its own renewal client. Adapt legacy sessions to project/workspace only. `GrantKeeper.fetch` remains the transport pattern, with a typed recall renewal endpoint adapter. Tool registration selects the credential kind; model arguments never choose grant kind/token. A conversation-only session constructs no project capability client. Parallel recall/project calls must never overwrite one another's credentials.

TanStack Query owns context responses; keys include actor, thread and requested revision. Bind initiating identity into mutations and ignore stale view completions, preserving #1964's pending-save isolation. Chat-store remains transcript owner. The browser shows freshness, partial coverage, source previews, owner annotation controls, Markdown export and the exact external selection. `CONVERSATION_CONTEXT_ENABLED` gates generation; `NOUS_CONVERSATION_MCP_ENABLED` plus `NOUS_MCP_ENABLED` gate external recall. Disabling generation preserves authorized existing native reads and revocation.

## 6. Plan 05: consent and atomic acceptance

Add project-only `workflows:run` when its enforcement lands. Existing direct tools keep their separate scopes. Browser-only workflow consent anchors to the consumed integration consent ID, actor, organization, project and device, plus immutable selected document IDs and optional `(thread_id,revision_id)` sources. Never anchor lifetime to one 15-minute grant ID: ordinary renewal revokes that row. Explicit consent/device revocation, expiry or current access loss revokes child authority; transport renewal is not cancellation.

Proposed policy remains `research_readonly_v1`: new-child mode authorizes a conversation destination, ten starts, one concurrent task and 24-hour expiry; existing-target mode authorizes exactly one idle, distinct thread and one start. Recheck target edit rights and source read rights at acceptance. Caller/model cannot choose another target, profile, parent run, quota or broader source set. At least one approved source is required; maximum 20 documents and five context revisions. Context-only tasks pass an explicit empty document allowlist.

`POST /api/v1/integrations/workflows` accepts extra-forbidden `request_id`, prompt (8,000 characters), approved-source subset and optional policy ID matching the attached consent. Canonical payload hash includes prompt, sorted source identities, policy/profile version and target policy; `(actor,consent,request_id)` is unique. Same payload replay returns the original task without quota debit; different payload is 409. Lock an existing target first, then consent/quota; create a new child target only after quota admission. Accept workflow/message/run/event/`agent.workflow.execute` intent atomically. Newly inserted run/workflow rows remain invisible until this transaction commits. Extract a transaction-internal submission helper behind the existing committing `accept_submission` wrapper; no second user-message writer or nested service commit. Use `project_thread_service.attach_thread_to_project` so column, join row and RAG scope agree.

Persist workflow IDs, source manifest, policy hash, parent consent, optional server-derived parent run, target, profile, counters/deadline, dispatch/execution fencing and completion/publication references. Mint a server-only child delegation with exactly `tools:read` and `artifacts:publish`, bound to this workflow/run/thread; no bearer token is returned or logged. Its expiry is capped by policy expiry and execution deadline, **not the replaced parent transport token**. The workflow guard explicitly rechecks consumed parent consent/device/current access on every operation: device-less internal grants currently bypass the external consent check and cannot substitute for this guard. Internal grants cannot delegate again, share artifacts or run a harness.

## 7. Plan 05: restricted native profile and evaluation

Reuse native planner, LLM, compactor and reflection implementations in a profile-specific builder/runner. Include immutable profile version in graph cache keys and use checkpoint namespace `workflow:{workflow_id}`. Do not call the ordinary runner's ambient-history/project-memory/skill/store/preprocessing setup. Inputs are only the explicit prompt and approved sources; even an existing idle target contributes no historical transcript. Keep normal chat builder/cache behavior unchanged.

| Fixed budget | Enforcement |
| --- | --- |
| 20 node admissions | Persist before every node execution attempt, including retry, reflection and compaction; step 21 denied. |
| 20 tool invocations | Persist before each call, including calls within one model batch and retries; rejected excess calls never execute. |
| 300 seconds | Durable wall-clock deadline from first successful execution claim; checkpoint/restart cannot reset it. Per-call timeout is at most 30 seconds and remaining time. |
| Source/output bounds | Explicit source set; gateway results 64 KiB; one Markdown report at most 256 KiB; answer 16,000 characters, 50 refs, result envelope 128 KiB. |

Every admission checks cancellation, deadline, profile counters, consent/device/actor/tenant/current sources and target authority. Counters are monotonic, committed before external work; failure never refunds them. Durable invocation identities distinguish a completed receipt replay from a fresh attempt. Uncertain attempts are not replayed as new work. The deadline stops new effects even if a provider ignores cancellation; retain stopping/recovering ownership until execution cessation is established.

Allow only `search_documents`, `list_project_documents`, `do_kb_retrieve` through `read_tools.invoke_read`, plus `publish_research_report`. Add server-only `allowed_document_ids`: `None` preserves current direct-tool behavior; empty means deny document reads; workflows always pass a verified set. Apply restrictions before SQL ranking/limit and downstream retrieval, and check returned source identities. Reject injected tools at execution as well as advertisement. Exclude memory load/save, automatic frozen skills, specialized subgraphs, code execution, arbitrary web tools, approval interrupts, mutation, harness and workflow recursion. Optional context sources use Plan 04's strict read service and exact authorized revision; missing/invalidated versions fail explicitly.

**Evaluation prerequisite:** before profile changes, record a new baseline under `evals/baselines/` following `AGENT_FLOW_BASELINE.md`, with source/deployment/model/config/dataset/task/harness digests and environment. Use synthetic tenant-isolated research tasks and characterize current native behavior; this is not proof that the unrestricted default graph meets new workflow policy. Preserve normal-chat regression comparisons separately. For profile acceptance use at least five trials per capability, all objective safety gates passing, semantic success at least four of five, calibrated fidelity judgments and zero infrastructure failures. New workflow constraints need their own objective tests; mocked nodes do not establish answer fidelity. Missing provider/baseline evidence blocks profile implementation/rollout rather than manufacturing a green baseline.

## 8. Delivery, publication, cancellation and recovery

Extend the existing five-second dispatch task with a typed second handler for `agent.workflow.execute`; no `relay_nous_workflows` beat. Move generic pending-intent access behind submission/outbox service accessors; retain harness command creation in its handler. Apply flags per kind: harness disabled must not suppress authorized workflow dispatch, and workflow new-start disable must not disable reconciliation/cancel/status. Do not consume `agent.stream.execute` intents.

Use bounded per-kind scans (100 each) with deterministic ordering, eligibility filtering before limit/keyset progress and run-first `SKIP LOCKED` claims. Workflow-specific delivery lease/fencing fields belong in its dispatch receipt; do not assume `AgentOutbox` already has them. Commit a scheduling lease, enqueue only workflow ID on the existing `agent_runs` queue, then stamp broker acknowledgement conditionally. Crash/ambiguous broker ack may redeliver the same ID; existing one-shot execution claim admits only one graph start. Never perform model/network work while holding row locks. Queued cancellation terminalizes only if execution was never claimed; races recheck under lock.

Extend the existing stale-run sweeper to delegate workflow rows to workflow reconciliation **before** Redis absence/native failure fallback. Redis TTL, expired scheduling lease or a missing poller does not prove execution stopped. Preserve checkpoints, counters, transcript/results and publication receipts in durable storage. A worker lost after execution claim enters `recovering`; inspect exact checkpoint/operation/terminal evidence. V1 does not resume uncertain graph work automatically or release its writer. Proven pre-claim delivery may retry; proven terminal state may repair projections. Otherwise show recovery required.

Publication wraps the existing artifact reservation/storage/finalization flow with workflow source/cancel checks and a deterministic workflow/tool-call publication identity. Require Markdown, cap bytes, reject changed-body identity replay, and commit metadata/receipt before reporting publication. Storage is outside the metadata transaction; failed finalization leaves a sweepable orphan, not a claimed artifact. Maintain #1965's run-before-event terminal serialization.

Cancellation racing finalization is serialized at the run/workflow guard: if cancellation wins, no new artifact commits; if publication commits first, its artifact remains durable and is labeled partial when the task later cancels/fails. Do not undo published state or report workflow success merely because an artifact exists. Success requires terminal native state, persisted assistant output and exact publication/result references. Final success/result/event projection commits atomically through existing run services. Traces and Redis are never completion evidence.

Use the same cancellation path from external and browser-owner routes. Running cancellation persists intent and waits for stopped execution; uncertainty remains recovering. A server-verified parent cancellation requests child cancellation idempotently; ordinary parent completion does not. Polling never restarts work. Replacement grants from the same live consent may get/cancel the task; revoked external credentials cannot. Browser status/cancel checks owner and current access independently without reviving credentials. Source revocation suppresses derived results rather than exposing uncited prose; safe owner status/cancellation remains available when source text is no longer readable.

For existing rows, use writer target (only where the native writer protocol requires it) → run → workflow → consent/policy → operation/outbox/publication/event rows. Generic run-first dispatch paths need no consent lock. Revocation commits the consent change and releases its lock before requesting run cancellation in a separate idempotent transaction; it never waits for a run while holding consent. Acceptance may lock consent before inserting its new, externally invisible run/workflow rows, but may not then lock another existing target/run. Publication locks the existing run/workflow and consent, rechecks live authority, and commits its receipt under those locks; upload and storage probes occur before this final critical section. This gives cancellation/revocation a concrete commit order without reversing #1965's run → outbox/command/event ordering. Prove the actual cross-service order with blocked two-connection tests before implementation acceptance.

## 9. Tracing and user experience

Create server correlation IDs from authorized stored actor/workflow/run linkage. Ignore external `langsmith-trace`, `baggage`, `traceparent`, `tracestate` and foreign echoed correlation; only trusted internal workers receive stored parent context. Export allowlisted bounded IDs, status and timing only. Profile-owned SDK clients/callbacks redact **all descendant** LLM/tool spans in deployed, local and test environments; do not race normal chats with process-wide tracing toggles. If descendant isolation cannot be proven, disable automatic profile instrumentation and emit explicit metadata-only spans. Trace exporter failure never changes acceptance/outcome. A local SDK ID is not hosted trace proof.

Browser consent displays source selection, target mode, fixed budgets, start/concurrency ceilings and expiry; enabling consent alone starts nothing. MCP explicitly exposes start/get/cancel task tools under workflow permission, using the current keeper transport. UI shows queued/running/stopping/recovering/terminal states and actual child-thread/artifact links. New-start flags stay off until live acceptance. No automatic polling-to-start, scope expansion or hidden consent renewal is allowed.

## 10. Threat, race and failure acceptance matrix

| Scenario | Required observable result / evidence |
| --- | --- |
| Insert/update/upsert/raw SQL/delete across every message writer | PostgreSQL trigger changes exactly the intended counters; feedback and duplicate no-op do not. Disable trigger and prove failure. |
| Edit/delete/backdated insert during generation | Candidate CAS loses; invalidated old text/links stay hidden after rebuild and export. Mutate source/epoch guards. |
| 201 messages, huge UTF-8 message, model failure, empty thread | Resumable bounded pages, explicit partial/error coverage, no fake completion; empty needs no model. Live fidelity tests distinguish decisions from assistant claims. |
| Concurrent owner annotations/refresh | One annotation CAS winner; exact pin text retained, no model rewrite or stale overwrite. Mutate revision guard. |
| Foreign public thread, omitted selection, removed membership/ancestor | No search rank/count/snippet/source/body leakage; test before filtering and revocation during retrieval. |
| Recall/project requests in parallel; account/thread switch during save | Correct grant per tool and initiating cache key; no stale/private response in active view. Mutate identity guards. |
| Grant renewal, consent/device revoke, expired policy | Renewal preserves selected authority/task identity; explicit revoke blocks the next operation and results; no child authority survives consent. Test both transaction orders. |
| Concurrent same/changed request IDs and quota race | One task/thread/debit; changed canonical payload 409; concurrency/start ceilings never overshoot. Real two-connection PostgreSQL and mutation proof. |
| Prompt injects forbidden tool, ambient target memory/history, unselected high-rank document | Zero forbidden invocation or ambient source; selected SQL filtering precedes limit; empty document set reaches no document backend. |
| Node/tool 21, batched calls, retry, restart/deadline | Durable budgets never reset/refund; denied work has zero effect; same checkpoint cannot replenish allowance. |
| Duplicate broker delivery/crash before claim/after claim | One execution; pre-claim retry safe; post-claim uncertainty recovering with writer retained. Remove claim guard and prove duplicate-start test fails. |
| More than 100 permanently ineligible pending rows | Every eligible tail can progress; per-kind fairness and filtering/keyset scan prevent starvation. |
| Cancel/revoke between read, upload and artifact commit; terminal-event race | Guard wins prevent new publication; prior committed artifact remains truthful partial evidence; terminal ledger accepts no late artifact event. Two-connection PG tests. |
| Redis expiry, storage outage, lost worker/checkpoint, disable flags | No false success/restart/unlock; durable status/cancel/reconciliation available; orphan upload swept. |
| Forged tracing context/export outage/secret sentinels | Server correlation only; inspect every descendant span's payload/error; no content export or outcome dependency. |

## 11. Delivery sequence and approval gates

1. After written-spec approval, write a task-level implementation plan with concrete tests/mutations, owners and execution choice. Reconfirm fresh code and any changes while #1964/#1965 merge; this proposal grants no execution authority.
2. After the preceding migration actually merges: Plan 04 persistence/triggers/coverage migration, backfill and native context service. Prove PG upgrade/downgrade and counters before merging. Next migration branch starts only after this one merges and single-head verification repeats.
3. Plan 04 separate recall-consent/grant migration, narrow APIs/MCP/UI and native annotations/export. Keep generation/external flags off until their respective proofs. Regenerate OpenAPI and frontend types with every HTTP schema change.
4. Record the pre-profile eval baseline before changing graph behavior. Plan 05 workflow policy/receipt/counter migration follows the preceding merged head; acceptance + shared dispatch + profile + publication/recovery are feature slices of that one reviewed schema design, not concurrent migration branches.
5. Run canonical backend/frontend/bridge gates and meaningful affected suites, real PG two-connection races, and mutation checks. Preserve current default graph, direct tools, route boundaries, quality baselines and old credential compatibility.

**Live gates remain NOT RUN in this design pass.** Before enabling Plan 04: real project and projectless chat, multi-page coverage, edit/delete invalidation, independent pins, managed/standalone selective recall and revocation; configured-model synthetic fidelity. Before enabling Plan 05: managed and standalone explicit start/status/cancel, separate child identity, real selected retrieval, durable Markdown checksum, quota exhaustion, transport renewal, worker-loss recovery and metadata-only hosted traces when configured. Record code/image/flags, consent/task/run/checkpoint/revision/artifact IDs and checksums without private text or secrets. Hosted CI, protocol mocks, local PostgreSQL and live model/deployment journeys are separate evidence. Provider/storage/browser/trace unavailability is BLOCKED or NOT RUN, never a semantic pass.

**Decisions requested at spec review:** approve the recommended trigger/separate-recall-grant/shared-relay architecture; the fixed TTLs/budgets and consent-lineage semantics; publication-before-cancel partial-artifact behavior; and the serial delivery sequence. Any change to these decisions precedes implementation planning.
